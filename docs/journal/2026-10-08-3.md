# 2026-10-08 — Session 5: see and measure the corpus

## Goal

The owner asked why 115,000 text works weigh 1 GB, then asked to start looking at the corpus as
soon as possible, "with respect and a hard data background", so that what the exploration finds
can constrain the roadmap early. He also asked for a viewer to share the same picture.

## Done

- **Corrupt SAUCE records set aside** (#52, ADR 0015): about 135 grids had 8,224 to 30,061
  columns because the binary fields of their SAUCE records were text, shifted bytes or space
  padding. A record with an undefined type pair or a size larger than the file gives no width
  and no flags; `decoding.sauce_problems` names the evidence. Decoder version 2; the corpus was
  decoded again (567 records set aside, widest grid now 2,660 columns).
- **Roadmap** (#53, #54): preservation copies and package planned later; exploration moved
  before D1, on the `train` packs only (research program, rule 3).
- **Feature extractor v1** (#55, ADR 0016): geometry, glyphs, colour, sequence; `features`
  table, published as `features.parquet`; version guard extended; golden features pinned.
- **Dataset `works`, split views, exploration notebook** (#56).
- **`--shard i/n`** for `tm render` and `tm features` (#57); **index on representations** (#58).
- **Corpus explorer** (#59, `just explore`): a local wall of first screens, filters, sort by
  feature, detail with record, measures, CP437 glyph pairs and nearest works.
- **First exploration note** (this pull request): research/exploration/works.md.
- All of 16colo measured (111,453 grids); about 80,000 conservation renderings, the rest running.

## Decisions

- Trust a SAUCE record's numbers only when it is coherent, rather than cap widths (ADR 0015).
- Exploration reads the `train` packs only; a file is `train` only when every pack holding it is
  (views `pack_split`, `work_split`, migration 0005; research program, rule 3).
- Features live in a table and are published as Parquet (ADR 0016; foundation document amended).
- The corpus explorer is a research tool on localhost, not the museum's API.

## Problems met

- The pre-push hook checks the whole working tree, so untracked work in progress blocks a push
  on another branch: lint it first or stash it.
- `pkill -f` matched the shell running it and killed the command twice: kill by PID.
- The dataset query scanned `representation` once per work: the index was missing (#58).
- A filter race in the explorer showed only in screenshots; looking at the rendering found it.

## Field notes added

- A broken SAUCE record is a tool's fingerprint (`-EnCrYptEd by iLL`, RiSE's shifted record,
  space padding).
- The nineties drew with eight backgrounds: the blink bit is as rare as the iCE flag.
- "ASCII" files were often coloured.

## State at the end

`main` green. The renderings of the last third of the corpus are still running (7 shards); the
explorer previews the others from their grids. Nothing uncommitted.
