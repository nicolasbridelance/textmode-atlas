# 2026-10-09 — Session 7: the text layer of the whole corpus

## Goal

Leads I2, proposed by the handover of session 6: the words written inside every work, stored,
published in a dataset and searchable, as a base for signatures (Q12), languages (Q10) and
greetings.

## Done

- **Text extractor, versioned** (#71): `tm_analysis.text` is now pinned like the features
  (ADR 0012, `TEXT_VERSION`). Migration 0008 adds `text_layer`: one row per grid and extractor
  version, with its lines and their grid rows; a grid without words gets an empty row, so a rerun
  reads nothing. `tm text --shard i/n`.
- **Text v2**, same pull request: v1 kept printable ASCII only, so é, ü, ñ, ß became spaces and
  split words. v2 keeps CP437 letters 0x80–0xA5 and ß; a word needs one ASCII letter or digit,
  so rows of Ñ or ¢ drawn as texture stay out.
- **Corpus runs**: v1 then v2 over 109,405 grids (about an hour each on 8 shards, almost all of
  it reading grids from the bucket). v2: 1,172,985 lines; about 9,600 grids hold no word.
- **`works` v4**: table `text` (912,256 lines of the train packs). The datasheet says it quotes
  the works, one more reason the dataset stays local.
- **Explorer**: "words in the work" search, accent-insensitive (`grusse` finds `grüsse`), the
  first matching line on each card; the detail reads the dataset instead of decoding the grid.
  Checked in screenshots, desktop and phone.
- Tests: the features and text-layer tests share a `horizon` fixture and one parametrized
  integrity test (jscpd found the copies).

## Decisions

- The text layer is stored in the database like the features, not computed by the explorer:
  the API's search will read the same rows later. Research searches it in DuckDB over
  `text.parquet` (under 100 ms); no Postgres text index until the API needs one (YAGNI).
- v1 rows stay in `text_layer` as history, as decoder versions do.

## Problems met

- CP437 has no ã or õ; a test written with `não` could not be encoded. The decoder is right,
  the scene had to work around it (field note).
- `tm.text` would have shadowed `sqlalchemy.text` in imports: the module is `tm.text_layer`.

## Field notes added

- What the works say in letters: BBS vocabulary in 44% of the ANSI of 1990–93, falling to
  7–12%; greets peak in 1994–96.
- CP437's letters: a Brazilian text writes `näo` with the German ä; Polish texts drop their
  diacritics; Ñ is texture; non-English writing stays under 1% per era.

## Part 2, same day: sources, Wikipedia, D1

The owner approved the refactor, left the D1 strata and Demozoo access to the data ("fais au
mieux, M. le data scientist"), and asked for a register of the cartography's sources, what could

### Done

- **Refactor** (#72): `tm.grids` reads a stored grid and checks it, and lists the grids an
  extractor has not read; render, features and text use it. 44 lines fewer.
- **Source register** (#73): [docs/sources/README.md](../sources/README.md) ranks the sources
  (in use, fast, medium, later), with figures measured at the source and what the cartography got
  wrong (a Demozoo license that does not exist, citations that do not support their claims,
  sources it missed). Source notes for Demozoo, textfiles.com and Wikipedia.
- **Demozoo access, solved**: Demozoo publishes a daily dump of its whole database
  (data.demozoo.org, 200 MB); loaded locally into a separate `demozoo_raw` database. Pouët
  publishes weekly JSON dumps; Defacto2 a daily SQL export. Downloads in `data/`, with their
  SHA-256 in the source notes' sense.
- **Wikipedia**: 29 topics in 70 languages, searched in 22; Wikimedia wants a
  `name/version (url)` User-Agent.
- **Three archives** ([archives.md](../../research/exploration/archives.md), Q21 exploratory):
  16colo, textfiles.com and Demozoo all peak in 1996–97, but 92% of textfiles' packs have a 16colo
  namesake: one lineage, no independent witness.
- **D1** (ADR 0017, step 6 of the roadmap): seven eras bounded by the mass, three packs each,
  systematic within the era over content and size, seed 20261009, weights N/n; three packs added
  by hand (acdu1190, the 16colo collection `1991`, Black Maiden's maiden14), each with its
  reason. `tm dataset draw` freezes `datasets/d1/sample.yaml`; `same_as` tables reuse the
  catalogue and works definitions. Built: 24 packs, 1,563 files, 655 works, 6,741 lines of text.
- **Templates**: `research/templates/hypothesis.md` and `notebook.py` (design-weighted mean,
  pack bootstrap within strata; on D1, coloured block art is 69% of a pack's works, 56–82%).

### Decisions

- D1 strata and allocation: ADR 0017. Equal allocation over square-root (which leaves 2005–12 a
  single pack); implicit stratification by sorting over a two-way design 21 packs cannot fill.
- External dumps are read in their own local database, never in the museum's schema, until an
  import writes assertions with their source.
- The register supersedes the cartography's tables; the cartography keeps a pointer to it.
