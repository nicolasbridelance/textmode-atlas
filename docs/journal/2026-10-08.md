# 2026-10-08 — Session 3: from Horizon to real packs

## Goal

Run the pipeline end to end on the golden source, then on real 16colo packs, so that research
phase R0 can start.

## Done

- **Pipeline on the golden source**: `tm ingest golden` (#29), `tm decode` with grids in the new
  private bucket `tm-derived` (ADR 0011, #30), explicit decoder and renderer versions guarded by
  a source digest (ADR 0012, #31), `tm render` conservation PNGs with recipes (#32).
- **Roadmap reordered with the owner** (#33): real packs, catalogue exploration, features, D1,
  then `tm export` and a first work screen; what nothing depends on yet is listed as later.
- **16colo**: source note (#35, first M0 note), full mirror of `archive-pack` in `data/16colo/`
  (5,860 archives, 9.1 GB; six packs refused by the server).
- **`tm ingest pack`** (#36, ADR 0013): archives read by Python, Info-ZIP, 7-Zip 23.01 and arj,
  checked by CRC, installed by `scripts/install-archive-readers.sh` in the image and in CI; art
  found by extension, SAUCE or content; reruns complete earlier runs. All 304 packs of 1990–1993
  ingested locally with no error: 7,289 art works.
- **`tm decode` / `tm render` at scale** (#37): one transaction per artifact, no grids held in
  memory; the 7,225 ANSI files of 1990–1993 decode with no error.
- **Field notes** started (#38), and the rule to keep them in CLAUDE.md.
- Devcontainer: `libmagic1` for reuse (#34). Local Git LFS hooks removed (not from the repo: written
  by the clone; the project does not use LFS).

## Decisions

- Grids and renderings live in a third, private bucket (ADR 0011): rebuildable, not copied three
  times like originals, never in the public bucket. My first idea (a prefix in `tm-originals`)
  contradicted the foundation document.
- Decoder and renderer versions are explicit, and a test fails if their code changes without a
  bump (ADR 0012).
- Four archive readers, chosen by measurement (ADR 0013); `unar` rejected for returning wrong
  bytes without failing.
- Explore the whole catalogue before drawing D1 (owner): representativeness needs to know what
  there is to represent. D1 is drawn by stratum with a fixed seed.
- Storage estimate, given to the owner: all of 16colo with derived data about 30–40 GB; with the
  M5 sources 60–220 GB, mostly depending on how much of IF Archive and scene.org is in scope. The
  repository never holds artworks; cold storage is object storage (host decision, M0).

## Problems met

- `tm decode` held every grid in memory and was killed on 7,225 files (fixed, #37).
- Skipping known packs would have left them incomplete forever and lost packs first met inside
  another pack (fixed before merge, #36).
- Before SAUCE, art is often named by group tag (`.MIR`, `.SDA`…): 2,739 ANSI files were missed
  until content detection (fixed before merge, #36).
- An ADR table first reported readers' scores I had not measured ("4 / 4"); corrected before
  merge. Check every figure against a command output before writing it.
- The `web` CI job sometimes spends 20 minutes in `playwright install --with-deps`; the
  Codespaces token cannot cancel or rerun runs (403).
- With LFS hooks present, pre-commit could not restore unstaged files; gone with the hooks.
