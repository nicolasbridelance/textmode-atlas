# 2026-10-09 — one museum for exploration and research

## Goal and result

At the owner's request, fuse the research viewer and museum. Collection/search,
constellation, dated scientific reports and the shared work screen now belong to
one localized Svelte museum, served locally with `just museum` (`just explore` alias).
The previously authorized Wi-Fi URL now serves this museum.

## Decisions

[ADR 0027](../adr/0027-one-museum-for-exploration-and-research.md) records the decision;
the foundation was updated before code. The existing pipeline and frozen research
datasets remain reproducible. One interface retains source/conservation/interpretation
distinctions, display rights and audience restrictions. Work records accept validated
explanations, scientific readings and vision judgements with signed origin, method,
uncertainty and model/input/prompt identity. No model output is fabricated and opening
the museum makes no model call. Scientific reports retain their dates and scope.

## Validation and state

Detailed evidence: [EV-008](../setup/JOURNAL.md#ev-008--unified-museum).
Linux `just check` passed: 311 Python tests, 11 web unit tests, critical policy coverage
100%; production build and 5 existing e2e tests passed. Real-corpus desktop/mobile
Chromium paths and HTTP refusals were checked. Browser errors: zero. The local Wi-Fi
forward responds with the unified rooms; phone-side acceptance remains the owner's.

The standalone HTML interfaces were replaced by native rooms, retaining the graph
runtime. No additional cleanup is needed beyond this authorized fusion. Existing
migration duplication and Vitest shutdown warning remain intentional/known debt.
No historical field finding was produced by this UI consolidation; existing leads
Q33/I42 still govern future model evaluation rather than claiming it has happened.

Branch `feat/unified-museum`, local only. Public exports, interpretation authoring and
model evaluation remain future work; see [operation and limits](../unified-museum.md).
No private datasets, originals, dumps, credentials or local screenshots enter Git.
